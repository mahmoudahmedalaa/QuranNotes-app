Three separate proof layers

1. Deterministic / structural

npm run noor:verify

Corpus integrity, tests, builds, contracts, exact cases.

2. Real semantic retrieval

npm run noor:verify:retrieval

Real Vertex embedding + promoted Firestore corpus, read-only.

3. Authenticated live

npm run noor:verify:live

Auth + App Check + retrieval + generation + citations + conversation state.

Promotion discipline

stable-v1 ↓ candidate ↓ noor:verify ↓ noor:verify:retrieval ↓ deploy only askNoorRagV1 ↓ noor:verify:live ↓ PASS → stable-v2 FAIL → rollback to stable-v1

This is why experimental candidates can fail without silently degrading the known-good production baseline.

RAG in plain English

RAG = Retrieval-Augmented Generation. Instead of trusting only the language model's memory, you retrieve trusted information relevant to the question and make that information the model's temporary working context.

The five concepts to understand

Query understanding

“Its significance” becomes meaningful only when paired with validated conversation state such as Surah Al-Baqarah.

Semantic retrieval

Embeddings let “Noah” retrieve source text that says “Nuh.”

Lexical retrieval

Exact words and references still matter, so Noor combines lexical and semantic search.

Answerability

A chunk may be mathematically similar without actually answering the question.

Grounding + evals

The model can synthesize naturally, but specific failures become regression tests while general failure classes become reusable runtime capabilities.

The rule worth remembering

SPECIFIC FAILURE → EVAL CASE GENERAL FAILURE CLASS → REUSABLE CAPABILITY Example: “Noah” fails to retrieve “Nuh” → keep Noah as a regression test → fix semantic equivalence generically NOT: if question == Noah → return Noah chunk
